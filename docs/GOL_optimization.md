# Оптимизация чтения GOL и пост-обработки

История анализа ускорения пути `GOL → GeoObject` и выполненных оптимизаций.

## Что реализовано

### 1. Прямое чтение GOL через FFI (libgeodesk)

Изначально GOL читался через промежуточный PBF:

```
gol query <region.gol> '<GOQL>' -f pbf  →  temp .osm.pbf  →  osmpbf  →  GeoObject
```

Теперь при сборке с флагом `gol-ffi` GOL читается напрямую через C ABI поверх
C++-библиотеки libgeodesk — без подпроцесса `gol` и без промежуточного PBF:

- C ABI-шов: `gol-ffi/gol_ffi.{h,cpp}` (функции `gol_open`, `gol_iterate`,
  `gol_next`, `gol_tag`, `gol_type`, `gol_lon`/`gol_lat`).
- Rust-обёртка: `src/gol_ffi.rs` (`GolFfiSource` за трейтом `FeatureSource`).
- Сборка C++-части автоматизирована в `build.rs` (крэйт `cc`); источники
  libgeodesk/gtl берутся из `vendor/` или `LIBGEODESK_DIR`/`GTL_DIR`.

Извлечение переиспользует `extract_address`/`extract_named_object` из парсера и
повторяет логику `PbfParser::process_element` — поэтому **сырое извлечение
идентично PBF** (проверено на Калининграде и Central Fed District). Расхождение
после дедупликации — только из-за центроида (геометрический центроид libgeodesk
≠ среднее арифметическое нод).

### 2. Пространственная сетка для `infer_missing_cities`

Наивный поиск ближайшего города был O(n·m) (объект × город) и занимал ~14 минут
на Central Fed District. Заменён на точный поиск по равномерной сетке
(`src/parser.rs`): клетки обходятся кольцами, остановка — по нижней границе
расстояния. Результат идентичен полному перебору по `haversine_approx`.

## Замеры (Central Fed District, 868 МБ PBF, 15,4 млн фич)

| Этап | PBF (изначально) | FFI | FFI + сетка |
|---|---|---|---|
| Чтение источника | 731 с | 65,8 с | 65,8 с |
| `infer_missing_cities` | ~810 с | ~820 с | **7,6 с** |
| Полная сборка | 30:44 | 19:40 | **6:14** |

Результат сборки идентичен: 1 924 563 объекта (1 898 506 адресов + 26 057 POI).

## Оставшиеся варианты (не реализованы)

- **Стриминг PBF без temp-файла** — теперь неактуально (FFI читает напрямую).
- **CSV/GeoJSONL с центроидом от gol** — заменён FFI.
- **Нативный Rust-читатель GOL** — всё ещё опция, если понадобится избавиться
  от C++-зависимости. Формат публично не оформлен как открытая спека.

## Следующие узкие места

После оптимизаций основное время сборки Central Fed занимают:

1. нормализация названий (~3,5 мин);
2. SQLite-индексация (~1,5 мин);
3. чтение GOL через FFI (~65 с).
