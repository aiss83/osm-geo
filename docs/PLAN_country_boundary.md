# План: страна и граница страны в компактном формате

> **Статус:** реализовано для PBF и GOL (CLI + FFI). Формат — version 3 с
> полями `country_code`/`country_name` и секцией `Country Boundary`.

## 1. Цель и инварианты

- Один файл `.bin` = **одна страна** (вход — страновой PBF/GOL).
- Страна записывается **один раз** на файл, а не на каждый объект.
- В файл сохраняется **административная граница страны** (MultiPolygon).
- Понятие «регион» как выходная сущность **убирается**: всегда вся страна.

## 2. Текущее состояние (факты)

- `country` хранится только у POI: в Named-записи Record Block есть `country_idx`
  (`country_idx, city_idx, name_idx, category`).
- У адресов страна уже не сохраняется (убрана ранее).
- Геометрия границ в `.bin` отсутствует — admin-boundary relation отбрасывается.
- `PbfParser` хранит `node_coords` и центроиды ways, но не `way → refs`, поэтому
  полигон границы сейчас собрать нельзя без доработок.

## 3. Изменения модели и пайплайна

- Убрать поле `country` из `Address` и `NamedObject` (страна — атрибут файла,
  а не объекта).
- Убрать `infer_missing_countries` — карта «город → страна» теряет смысл.
- Убрать CLI-флаг `--region` / `-r`.
- Заменить `region` в `Header` и в `Metadata` на `country`.

## 4. Определение страны (по данным)

Страна определяется по relation `type=boundary` + `boundary=administrative` +
`admin_level=2`.

В файле таких relation несколько (сама страна + пограничные сегменты с соседями),
поэтому нужен дизъюнктор — наличие ISO-кода:

1. `ISO3166-1:alpha2` (2 буквы) — основной, однозначный;
2. bare `ISO3166-1`, если 2 заглавные буквы;
3. `ISO3166-1:alpha3` (3 буквы) → маппинг в alpha-2 по константной таблице;
4. fallback: самый частый нормализованный `addr:country` (alpha-2).

Если по данным файла страну определить не удалось — резервные источники:

5. **имя файла** — парсить название страны/код из имени входного файла
   (`russia-latest.osm.pbf`, `belarus.gol` и т.п.);
6. **пользователь** — флаг `--country RU` или интерактивный запрос при сборке.

Нормализуем код к **alpha-2 в верхнем регистре**. Храним страну в двух полях:
`code` (alpha-2, напр. `RU`) и `name` (текст, напр. `Россия`) — код для машины,
имя для описания/UI.

> **Практическая поправка:** в страновом файле `admin_level=2`-relation несколько
> (страна + соседи/пограничные сегменты), поэтому «взять первый с ISO-кодом»
> ненадёжно. Итоговый порядок: сначала большинство `addr:country` среди объектов,
> затем `admin_level=2` relation, чей ISO-код совпадает с определённым кодом страны.

### Проверено на `russia-260811.gol`

relation `boundary=administrative + admin_level=2 + name="Россия"` (1 фича):

| Ключ | Значение |
|------|----------|
| `name` | `Россия` |
| `ISO3166-1` | `RU` |
| `ISO3166-1:alpha2` | `RU` |
| `ISO3166-1:alpha3` | `RUS` |
| `ISO3166-2` | *(пусто)* |
| `wikidata` | `Q159` |

Всего `[boundary=administrative][admin_level=2][name]` в файле — 39 фич
(пограничные сегменты и соседние страны), поэтому отбор именно по ISO-коду
обязателен.

## 5. Формат v3

### 5.1. Заголовок

- Поднять `version` до `3`.
- Поле `region: [u8; 46]` заменить на страну в двух полях:
  - `country_code` — alpha-2, напр. `RU` (короткий ASCII);
  - `country_name` — текст, напр. `Россия` (через String Pool или
    фиксированный UTF-8-буфер).

### 5.2. Записи

- Named-запись Record Block: убрать `country_idx` →
  `(city_idx, name_idx, category)`.
- Address-запись не меняется (`city_idx, street_idx, housenumber_idx`).

### 5.3. Новая секция «Country Boundary»

Секция с геометрией границы страны, структура MultiPolygon:

```
bbox:             (min_lat, min_lon, max_lat, max_lon)  — быстрый первый фильтр
country:          u32 (или строка кода)
polygon_count:    u32
per polygon:
  ring_count:     u32
  per ring:
    point_count:  u32
    points:       (lat, lon) * point_count
```

`bbox` позволяет отсечь точку за O(1) до запуска point-in-polygon (ray casting
по кольцам). Роли `outer`/`inner` кодируются порядком колец в полигоне (первое
кольцо — внешнее, остальные — дырки), либо явным флагом.

Точность координат — решение ниже (п.7).

## 6. Извлечение границы

1. Найти relation `admin_level=2` с ISO-кодом (см. п.4).
2. Собрать member-ways: нужен `way_id → Vec<node_id>` (сейчас хранится только
   центроид) + `node_id → (lat, lon)`.
3. Сшить way-сегменты в кольца по общим узлам; учесть роли `outer`/`inner`.
4. Собрать полигоны (страна может быть несвязной: РФ = основная часть +
   Калининградская область + острова).
5. Вычислить `bbox` всей границы (min/max lat/lon) — сохраняется первым полем
   секции для быстрого отсечения.
6. Опционально упростить (Douglas–Peucker) для уменьшения размера.

Для GOL-пути геометрия relation доступна напрямую, поэтому часть пунктов 2–3
может быть проще.

Память: хранить только ноды/ways, входящие в граничный relation, а не все.

## 7. Принятые решения

- **Точность координат границы:** `f32` (погрешность ~1 м достаточна для
  проверки покрытия страны).
- **Состав границы:** полный MultiPolygon — внешние кольца + внутренние
  «дырки» (анклавы других стран).
- **`country_name`, если известен только код:** fallback по небольшой карте
  `alpha-2 → имя` для основных стран; если неизвестно — пустая строка.
- **Граница не найдена:** предупредить в логе и собрать файл без секции
  границы (не падать); страна всё равно сохраняется.

## 8. Этапы реализации

1. Рефакторинг модели: убрать `country` из `Address`/`NamedObject`, убрать
   `infer_missing_countries`, убрать `--region`.
2. Определение страны по цепочке: `admin_level=2` + ISO3166 → имя файла →
   пользователь (`--country`/промпт); хранить `code` + `name`.
3. Формат v3: header (`country_code` + `country_name`), Named-запись без
   `country_idx`.
4. Секция Country Boundary + извлечение геометрии из PBF/GOL.
5. Тесты (roundtrip, отбор страны, геометрия), обновить `inspect_bin.py`,
   `DATABASE.md`, C-структуры, `README.md`.
6. Бенчмарк на России (размер/время/точность границы).
