# osm-geo

ETL-пайплайн для подготовки офлайн-базы геокодирования из OpenStreetMap.

Программа загружает PBF-файлы OSM (локально или с Geofabrik), извлекает адреса и POI, строит полнотекстовые и пространственные индексы, и формирует готовую базу для мобильных устройств (Android / iOS). Встроенный поисковый движок отсутствует — потребителем является сторонняя мобильная библиотека.

## Возможности

- **Два формата вывода:**
  - **SQLite** (`.db`) — FTS5 + B-tree, для отладки и поиска на устройстве
  - **Compact binary** (`.bin`) — в 4–6× компактнее SQLite, без внешних зависимостей
- Сжатие Zstandard (`.zst`) для транспортировки
- Стемминг русского языка (snowball) на этапе сборки — поиск с учётом склонений и падежей
- Транслитерация кириллицы: запросы латиницей (`moskva`) находят объекты «Москва»

### Очистка и нормализация данных

- **Коррекция опечаток** (SymSpell) с защитой типов улиц и названий городов от ложной перекоррекции
- **Нормализация падежей** типов улиц: «проспекту» → «проспект», «улицы» → «улица»
- **Согласование прилагательных** не только с типами улиц, но и с любыми существительными: «Калининградской зоопарк» → «Калининградский зоопарк»
- **Привязка к городам:** адреса и POI без `addr:city` автоматически привязываются к ближайшему населённому пункту по координатам (Haversine distance)
- **Склеивание опечаток в городах:** «Калининнград» → «Калининград» и аналогичные опечатки исправляются по редакционному расстоянию
- **Привязка к стране:** для объектов без страны код определяется по городу (карта «город→страна») или из параметра `-r` (напр. `RU-CFD` → `RU`)
- **Центроиды relation:** для POI-отношений вычисляются реальные координаты по members (ранее было (0, 0))

### Фильтрация POI

В базу попадают именованные объекты двух категорий:
- **historic** — памятники, мемориалы, объекты культурного наследия
- **tourism** — зоопарки, музеи, отели, достопримечательности

Остановки транспорта, дороги, офисы, природные объекты и прочее — не включаются.

- Автоматическая загрузка PBF с Geofabrik по имени региона
- Авто-распаковка `.gz` / `.zst` PBF-файлов

## Установка

### Базовая сборка (rule-based нормализатор)

Без внешних зависимостей — работает на всех платформах «из коробки»:

```bash
git clone https://github.com/aiss83/osm-geo.git
cd osm-geo
cargo build --release
```

Бинарный файл: `target/release/osm-geo`

Нормализатор названий включён по умолчанию и обрабатывает:
- Раскрытие сокращений: `ул` → `улица`, `пр-т` → `проспект`, `пл` → `площадь` и ещё 15+
- Нормализацию падежей: `улицы` → `улица`, `проспекту` → `проспект`
- Комбинации: `пр-ту Мира` → `проспект Мира`

Точность rule-based нормализатора: **90.6%** (на эталонном наборе из 53 тестов).

### Сборка с нейросетевым нормализатором (ONNX)

Нейросеть (mt5-small, 300M параметров) повышает точность до **98.1%**,
исправляя согласование прилагательных: `Калининградской улица` → `Калининградская улица`.

**Установка зависимостей:**

Только ONNX Runtime требует системную библиотеку. SentencePiece — чистый Rust, без внешних зависимостей.

| Платформа | Команда |
|---|---|
| macOS (Homebrew) | `brew install onnxruntime` |
| Ubuntu/Debian | `apt install libonnxruntime-dev` |
| Arch Linux | `pacman -S onnxruntime` |

**Сборка:**

```bash
cargo build --release --features neural-normalizer,neural-tokenizer
```

**Размещение модели:**

Скачайте готовую модель из GitHub Releases:

```bash
bash models/download.sh
```

Или сгенерируйте самостоятельно — инструкция в [`models/README.md`](models/README.md).

Файлы модели в `models/`:

```
models/
├── normalizer_encoder.onnx   # 141 MB (INT8)
├── normalizer_decoder.onnx   # 269 MB (INT8)
└── spiece.model              # 4.1 MB (SentencePiece токенизатор)
```

При отсутствии модели нормализатор автоматически использует rule-based режим.

### Feature-флаги

| Флаг | Назначение | Зависимости |
|---|---|---|
| *(без флагов)* | Rule-based нормализатор (по умолчанию) | Нет |
| `neural-normalizer` | ONNX Runtime для нейросети | `libonnxruntime` |
| `neural-tokenizer` | SentencePiece токенизация (pure Rust) | Нет |

Пример: `cargo build --release --features neural-normalizer,neural-tokenizer`

## Использование

### Сборка базы

```bash
# Из локального PBF-файла → SQLite
osm-geo build --input data/region.osm.pbf --region RU-CFD

# Из региона Geofabrik (авто-загрузка) → компактный бинарный формат
osm-geo build --input russia/central-fed-district --region RU-CFD --format compact

# Из URL
osm-geo build --input https://example.com/region.osm.pbf

# Из сжатого PBF (авто-распаковка .gz / .zst)
osm-geo build --input data/region.osm.pbf.zst
```

На выходе создаются:
- `{stem}.db` или `{stem}.bin` — база данных
- `{stem}.db.zst` или `{stem}.bin.zst` — сжатая версия для передачи
- `{stem}.metadata.json` — метаданные (SHA-256, статистика, дата сборки)

При первом запуске автоматически скачивается словарь SymSpell (`ru_full.txt`, ~28 МБ) для исправления опечаток. Если словарь недоступен, сборка продолжается без коррекции.

### Просмотр регионов Geofabrik

```bash
# Список континентов и стран
osm-geo list

# Подрегионы России
osm-geo list russia
```

### Просмотр метаданных базы

```bash
osm-geo info --db data/cfd.db
```

### Тестовый поиск

```bash
osm-geo query --db data/cfd.db "Москва Тверская"
```

Поиск применяет русский стеммер — запросы работают с учётом склонений: «москва», «москве», «москвы» → один результат.

## Инструменты

### Инспекция PBF-файла

```bash
cargo build --release --bin inspect_pbf
./target/release/inspect_pbf data/region.osm.pbf
```

Выводит все элементы PBF, содержащие заданные имена или адресные теги (настраивается в `src/bin/inspect_pbf.rs`).

### Анализ компактной базы

В корне репозитория — Python-скрипты для инспекции `.bin`-файлов:

| Скрипт | Назначение |
|---|---|
| `inspect_bin.py` | Общая структура: заголовок, пул строк, первые записи индексов |
| `search_pool.py <file>` | Поиск строк в пуле по паттернам |
| `city_stats.py <file>` | Статистика распределения адресов по городам |
| `street_city_stats.py <file>` | Привязка улиц к городам |
| `poi_check.py <file>` | Распределение POI по категориям |
| `poi_coords.py <file> <name>` | Координаты конкретного POI |
| `check_all_bins.py <files...>` | Массовая проверка строк в пуле |
